# Corrección de regresiones del Terminal POS — 25 de agosto de 2026

Esta revisión corrige los fallos visibles en el Terminal POS que podían hacer que un catálogo válido apareciera como no disponible y deformar los controles del panel de venta.

## Causa del fallo de catálogo

El endpoint `/sales/get_products` podía responder correctamente, pero el renderizador del navegador fallaba después de recibir el JSON. En el segundo recorrido de las tarjetas se utilizaba `p.uoms` fuera del alcance donde se había declarado `p`. El `ReferenceError` era capturado por el mismo bloque que maneja errores HTTP, por lo que la interfaz mostraba **“No pudimos cargar los productos”** aunque el servidor hubiera respondido con éxito.

La corrección vuelve a resolver el producto mediante `const p = products[idx]` dentro de cada tarjeta antes de configurar sus unidades y cantidades. También se añadieron abortos para búsquedas anteriores, protección contra respuestas obsoletas, validación de la forma del JSON y mensajes de reintento controlados.

## Correcciones visuales

- El buscador reserva espacio real para el icono y evita que este se superponga al placeholder.
- El selector de cliente reserva espacio real para el icono y mantiene el texto legible.
- El formulario de promoción usa una cuadrícula propia; el campo ya no se colapsa y el botón **Aplicar** ya no ocupa todo el ancho.
- Los estilos del POS están aislados bajo `body.pos-page` para impedir interferencias de reglas globales.
- Se eliminó el bloque CSS duplicado de la plantilla y se consolidó el diseño en `static/css/sales_css/create_sales.css`.
- Se corrigió el desplazamiento cuando el menú lateral está contraído y el espacio reservado indebidamente entre 821 y 1024 px.
- Se mantuvieron reglas específicas para modo oscuro, foco visible y movimiento reducido.

## Resiliencia del endpoint

El catálogo ya no cae completo por una única configuración de producto dañada:

- una conversión UOM inválida se aísla y se intenta mostrar la unidad base;
- una regla de precio inválida se registra sin exponer la excepción al usuario;
- el producto afectado se marca como no disponible para venta, en vez de derribar todo el catálogo;
- la respuesta se entrega con `Cache-Control: private, no-store, max-age=0`;
- las búsquedas se limitan a 120 caracteres.

## Validaciones ejecutadas

- 92 pruebas estáticas focalizadas superadas; 3 pruebas dinámicas fueron deseleccionadas porque este entorno no incluye Flask.
- `static_release_audit.py`: superado.
- `ui_consistency_audit.py`: superado.
- 118 plantillas Jinja analizadas sin errores.
- JavaScript del POS validado sintácticamente con Node.
- Prueba real del renderizador en Chromium: 3 productos renderizados, sin `ReferenceError`, con cantidades UNIT y WEIGHT correctas.
- Prueba visual en Chromium a 1778×858, 900×800 y 387×857: sin solapamiento de iconos y sin colapso del cupón.
